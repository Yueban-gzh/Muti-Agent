# 可配置多智能体决策辅助系统 — 团队分工

> 版本：v1.0 | 适用：3 人组（后端 A + 后端 B + 前端）

---

## 一、总体分工

### 后端 A：应用层后端负责人

**一句话：** A 负责把系统「组织起来」，让前端能通过 API 顺利调用后端功能。

#### A 主要负责

1. **用户登录注册接口**
   - 注册接口、登录接口、退出登录、当前用户信息、token / session 管理。

2. **权限控制**
   - 普通用户和管理员区分；
   - 管理员接口权限校验；
   - 普通用户只能看自己的任务；
   - 未登录用户不能访问系统主要功能。

3. **任务调度接口**
   - 接收前端提交的问题、Agent 配置、用户权重；
   - 生成任务 ID；
   - 调用 B 的多 Agent 分析服务；
   - 返回任务状态和结果。

4. **历史记录接口**
   - 查询当前用户历史任务；
   - 查询某个任务详情；
   - 管理员查询全部任务。

5. **反馈接口**
   - 用户采纳某个 Agent、采纳综合建议、保存用户备注；
   - 防止非法提交。

6. **管理员接口**
   - 查看用户列表、任务列表、反馈记录、日志；
   - 管理 Agent 模板的接口入口。

7. **报告导出接口**
   - 调用 B 提供的数据，组织成 txt / markdown 报告，提供给前端下载。

8. **接口文档与联调**
   - 维护接口路径、请求字段、返回字段；和前端一起联调。

#### A 不负责

- 不直接写 SQL
- 不写 AI 生成逻辑
- 不计算相似度
- 不设计前端页面
- 不直接处理模型

#### A 的最终交付物

- 登录注册接口
- 权限认证模块
- 任务启动接口、任务结果接口
- 历史记录接口、反馈接口
- 管理员接口、报告导出接口
- 接口文档、统一异常处理

---

### 后端 B：数据库与 AI 核心负责人

**一句话：** B 负责系统真正「会分析、会存储、会计算」的部分。

#### B 主要负责

1. **数据库设计**
   - 用户表、决策任务表、Agent 配置表、Agent 输出表、评分结果表、相似度结果表、冲突检测表、用户反馈表、日志表。

2. **数据访问服务**
   - 用户创建、密码校验、用户角色查询；
   - 任务创建、任务结果保存、历史记录查询、反馈保存、管理员数据查询。

3. **Agent 模板库**
   - 默认 Agent 模板、人设字段、Prompt 模板、模板增删改查、启用 / 禁用。

4. **Prompt 构建**
   - 根据用户问题、Agent 人设、决策模式、输出格式约束生成 Prompt。

5. **多 Agent 分析**
   - 根据用户选择的 Agent 数量（2—5）生成多个 Agent；
   - 每个 Agent 输出不同角度分析；生成结构化回答。

6. **评分矩阵**
   - 收益潜力、成本可控性、风险可控性、技术可行性、执行可行性、长期价值；
   - 根据用户权重计算综合得分。

7. **相似度计算**
   - 对 Agent 回答做向量化、两两相似度、判断观点是否重复、保存结果。

8. **冲突检测**
   - 根据评分差异判断主要分歧、输出冲突维度、生成冲突解释。

9. **综合建议生成**
   - 综合多个 Agent 回答，结合评分、权重、相似度、冲突点，输出最终建议。

10. **日志与异常**
    - 数据库异常、模型异常、生成失败、fallback 兜底结果。

#### B 不负责

- 不负责页面、不负责所有 API 路由
- 不负责前端状态管理、不负责 PPT 页面设计

#### B 的最终交付物

- SQLite 数据库、数据库初始化脚本
- `auth_store`、`task_store`、`agent_template_service`、`debate_service`、`feedback_store`
- Prompt 构建模块、多 Agent 生成模块
- 评分矩阵模块、相似度模块、冲突检测模块、综合建议模块

---

### 前端：交互与可视化负责人

**一句话：** 前端负责让系统「看起来像一个完整产品」，并保证验收时演示流畅。

#### 前端主要负责

1. 登录注册页面（表单、失败提示、登录状态、退出）
2. 决策任务创建页面（问题输入、示例问题、决策模式、Agent 数量、推荐 Agent）
3. Agent 配置页面（动态卡片、模板选择、名称/背景/立场/重点/风格）
4. 权重设置页面（六维权重、总和 100% 校验、默认与恢复）
5. 分析运行中页面（加载、状态轮询、失败提示）
6. 结果展示页面（Agent 卡片、评分矩阵、排名、相似度图、冲突点、综合建议、采纳按钮）
7. 历史记录页面（列表、详情、采纳结果、报告导出）
8. 管理员后台页面（用户、任务、反馈、日志、模板管理）
9. 可视化（Plotly 柱状图、评分对比、相似度图、综合排名图）
10. 演示准备（演示问题、账号、截图、答辩流程）

#### 前端不负责

- 不直连数据库、不调用模型、不自己生成 AI 回答、不自己计算相似度

#### 前端的最终交付物

- 登录注册页、任务创建页、Agent 配置页、权重设置页
- 结果展示页、历史记录页、管理员后台页
- Plotly 可视化图表、演示脚本、PPT 截图素材

## 三、三人之间的对接关系

### 1. A 和 B

**B 提供 service，A 包成 API。**

| B 提供 | A 暴露 |
|--------|--------|
| `verify_password()` | `POST /auth/login` |
| `DebateService.start()` | `POST /debate/start` |
| `get_task_detail()` | `GET /history/{task_id}` |
| `save_feedback()` | `POST /feedback/vote` |

这样 A 不碰数据库，B 也不用写一堆 API 路由。

### 2. A 和前端

A 给前端稳定接口。前端只需要知道：接口地址、请求字段、返回字段、是否需要登录、错误时返回什么。

**A 第一阶段要先给前端接口文档** → 见 [`api_contract.md`](./api_contract.md)。

### 3. B 和前端

B 和前端主要对齐**结果字段**（第二阶段前冻结），例如：

- Agent 名称、人设、回答
- 六维评分、综合得分
- 相似度矩阵、冲突点列表
- 综合建议、采纳结果

## 四、分阶段排期（2—3 周）

### 第一阶段：主流程跑通（3—5 天）

**目标：** 先让系统完整跑一遍（可不智能，用 mock）。

| 角色 | 要完成 |
|------|--------|
| **A** | 登录注册、权限、`/debate/start`、`/debate/status`、`/debate/result`、`/feedback/vote`、`/history/my`、接口文档初版 |
| **B** | 数据库初始化（users、decision_tasks、task_agents、agent_outputs、user_feedback）、默认 Agent 模板、mock 多 Agent 结果 |
| **前端** | 登录页、任务创建、Agent 配置、权重设置、mock 结果页、反馈按钮、历史入口 |

**阶段交付物：** 用户能登录 → 创建任务 → 看到 mock 分析 → 采纳 → 查看历史。

---

### 第二阶段：核心功能替换 mock（5—7 天）

**目标：** 体现项目核心亮点。

| 角色 | 要完成 |
|------|--------|
| **A** | 稳定所有接口字段、任务状态、结果查询、反馈接口、管理员接口初版、统一异常处理 |
| **B** | Prompt 构建、多 Agent 生成、评分矩阵、权重计算、相似度、冲突检测、综合建议、结果入库、日志 |
| **前端** | Agent 卡片、评分表、得分图、相似度图、冲突点、综合建议、历史详情 |

**阶段交付物：** 真实多 Agent 分析 + 评分 + 相似度 + 冲突 + 综合建议 + 可视化。

---

### 第三阶段：后台、报告和答辩准备（3—5 天）

| 角色 | 要完成 |
|------|--------|
| **A** | 管理员用户/任务/反馈/日志接口、报告导出、接口文档终版 |
| **B** | Agent 模板 CRUD、日志查询、历史详情、报告内容生成、演示数据 |
| **前端** | 管理员后台、模板管理、日志页、报告导出、界面美化、演示脚本、PPT 截图 |

**阶段交付物：** 普通用户 + 管理员流程均可完整演示。

## 五、开发优先级

### 必须完成（P0）

登录注册、权限控制、决策问题输入、Agent 数量/人设配置、多 Agent 分析、评分矩阵、用户权重、综合建议、SQLite 入库、反馈采纳、历史记录、基础可视化、管理员查看。

### 尽量完成（P1）

相似度计算、冲突检测、Agent 推荐、日志查看、报告导出、Agent 模板管理。

### 可以放到拓展（P2）

真正流式输出、多轮辩论、vLLM、模型量化、3D 语义图、PDF/Word 报告。

> 课程重点在完整 Python 应用（GUI、权限、网络、数据库、AI 核心、异常处理），不必把 vLLM 等压进验收主线。

## 七、最关键的协作规则

1. **A 不直接写数据库**（通过 B 的 `services` 访问）。
2. **前端不直连数据库、不直接调用模型**。
3. **B 提供 service，A 包成 API；A 提供 API，前端负责调用**。
4. **B 提供结果字段，前端负责展示**。
5. **接口字段变更必须三人确认**。
6. 进度快者可支援（如 A 帮前端写请求封装、B 提供 mock JSON），**不破坏模块边界**。
