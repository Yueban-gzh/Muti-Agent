## 1. 项目背景

在学习、创业、产品设计、项目管理、社团运营等场景中，用户经常会遇到需要综合判断的问题，例如：

- 是否应该投入时间开发一个校园二手交易平台？
- 创业团队应该优先做技术研发还是市场推广？
- 社团是否应该引入自动化报名和筛选系统？
- 公司是否应该投入预算建设 AI 客服？

这类问题通常没有唯一答案，需要从收益、成本、风险、技术可行性、执行难度、长期价值等多个角度综合分析。

传统单一 AI 问答工具往往只输出一个综合性回答，容易出现视角单一、风险提示不足、方案比较不充分等问题。因此，本项目设计一个**可配置的多智能体决策辅助系统**：用户可以根据问题特点配置多个 Agent，由不同角色的 Agent 分别分析问题，系统再对不同观点进行结构化比较和可视化展示。

课程指导书要求项目面向 AI 相关应用开发，重点考察 Python GUI、用户权限、网络功能、数据库操作、AI 核心功能、模块化设计和异常处理等能力，因此本项目将这些要求统一融入一个完整的 Python AI 应用中。

---

## 2. 产品定位

本系统定位为：**面向复杂问题分析的多智能体决策辅助工具**。

它不直接替用户做决定，而是通过多个不同角色的 Agent 帮助用户看到问题的不同侧面，最终辅助用户形成更全面、更理性的判断。

---

## 3. 产品目标

### 3.1 业务目标

1. 让用户能够输入一个复杂决策问题；
2. 让用户可以选择参与分析的 Agent 数量（2—5）；
3. 让用户可以自定义 Agent 的人设、立场和关注重点；
4. 让系统从多个角度生成分析结果；
5. 让系统判断不同 Agent 观点是否重复或冲突；
6. 让系统通过评分矩阵和用户权重生成综合建议；
7. 让用户可以采纳某个 Agent 或综合建议；
8. 让系统保存历史记录、Agent 配置和用户反馈。

### 3.2 课程目标

| 考察点 | 本项目体现 |
|--------|------------|
| Python GUI | Streamlit / PyQt 多页面交互 |
| 用户权限 | 普通用户 / 管理员，数据隔离 |
| 网络功能 | 模型权重或语料下载（requests） |
| 数据库 | SQLite 全表 CRUD |
| AI 核心 | 本地轻量模型 + 向量化 + 结构化评分 |
| 模块化 | api / services / db / ui 分层 |
| 异常处理 | 登录、DB、AI、网络各环节 try-except |

## 5. 用户角色

### 5.1 普通用户

**可以：** 注册/登录/改密；创建决策任务；配置 Agent 与权重；查看分析与图表；采纳方案；查看与导出自己的历史。

**不可以：** 查看他人数据；修改系统模板库；查看系统日志；删除他人任务。

### 5.2 管理员

**可以：** 登录后台；查看用户与全部任务；管理 Agent 模板；查看反馈统计与系统日志；导出数据。

**不可以：** 代替普通用户做决策（仅维护与验收展示）。

## 6. 核心业务流程

### 6.1 普通用户流程

```
打开系统 → 登录/注册 → 输入决策问题 → 选择决策模式
→ 选择 Agent 数量 → 配置 Agent 人设 → 设置决策权重
→ 开始分析 → 多 Agent 回答 → 相似度/冲突/评分
→ 综合建议 → 查看图表 → 采纳反馈 → 历史记录/导出报告
```

### 6.2 管理员流程

```
管理员登录 → 用户列表 → Agent 模板管理 → 全部任务
→ 反馈统计 → 系统日志 → 数据导出
```

### 8.3 Agent 配置模块

**亮点：** 用户可配置 2—5 个 Agent，每人设可自定义。

#### 8.3.1 Agent 数量

#### 8.3.2 预设模板（示例）

| 模板名 | 立场 | 关注重点 |

| 创新增长派 | 积极推进 | 增长机会、长期价值 |
| 风险审慎派 | 谨慎保守 | 失败风险、兜底方案 |
| 成本控制派 | 节约资源 | 投入产出、现金流 |
| 技术可行派 | 务实落地 | 实现难度、技术债 |
| 用户价值派 | 以用户为中心 | 需求真实性、体验 |

#### 8.3.3 自定义字段

| 字段 | 说明 |
|------|------|
| 名称 | 如「创新增长派」 |
| 模板 | 下拉选择预设 |
| 专业背景 | 如产品经理、风控专家 |
| 分析立场 | 积极推进 / 谨慎保守 / 中立 |
| 关注重点 | 多选或文本 |
| 输出风格 | 鼓励型 / 严谨型 / 简洁型 |
| 补充说明 | 可选 |

**验收：** 配置可入库；不同 Agent 回答能体现人设差异。

| 问题关键词示例 | 推荐组合 |
|----------------|----------|
| 技术、开发、系统 | 技术可行派 + 成本控制派 + 风险审慎派 |
| 创业、市场、推广 | 创新增长派 + 用户价值派 + 成本控制派 |
| 风险、上线、投入 | 风险审慎派 + 成本控制派 + 技术可行派 |

**验收：** 不同问题推荐不同；用户可修改后进入分析。

### 8.5 多智能体分析模块

#### 8.5.1 多 Agent 独立分析（P0）

**输入：** 用户问题、决策模式、Agent 配置、用户权重。

**输出：** 每个 Agent 一份结构化分析。

**建议输出格式：**

```
观点摘要：
核心理由：
收益分析：
成本分析：
风险分析：
执行建议：
适用条件：
维度评分：（六维 1—10 分）
最终建议：
```

**六维评分（分数越高越好）：**

| 维度 | 说明 |
|------|------|
| 收益潜力 | 长期收益与价值 |
| 成本可控性 | 成本是否可控（非「成本压力」） |
| 风险可控性 | 风险是否可管理 |
| 技术可行性 | 技术实现难度 |
| 执行可行性 | 团队与资源可执行性 |
| 长期价值 | 持续价值 |

#### 8.5.2 决策模式行为

- **多角度分析：** 各 Agent 独立输出。  
- **正反辩论：** Agent 分为支持方/反对方/中立评审。  
- **专家会诊：** 产品/技术/运营等角色分工。  
- **风险评审：** 侧重风险清单与是否建议推进。

#### 8.5.3 多轮讨论（P2，可选）

1. 第一轮：独立分析  
2. 第二轮：阅读他人摘要后补充/反驳  
3. 生成综合建议  

---

### 8.6 语义相似度与观点冲突

#### 8.6.1 语义相似度（P1）

**流程：**

1. 各 Agent 回答 → Embedding 向量；  
2. 两两余弦相似度；  
3. 生成相似度矩阵；  
4. 标记过高相似的对。

**规则示例：**

| sim 范围 | 含义 |
|----------|------|
| < 0.4 | 观点差异明显 |
| 0.4 — 0.7 | 部分重合 |
| > 0.7 | 高度相似，需提示或重生 |

**输出示例：**

```
Agent A ↔ Agent B: 0.72（偏高）
Agent A ↔ Agent C: 0.31（差异明显）
```

#### 8.6.2 观点冲突检测（P1）

**实现：** 用评分差异（课程版），某维度最高分与最低分差 ≥ 4 视为冲突。

**输出示例：**

> 主要冲突点 1：收益潜力判断差异较大——创新增长派认为长期收益高，风险审慎派认为不确定性大。

---

### 8.7 评分矩阵与权重

#### 8.7.1 评分矩阵（P0）

将自然语言转为可比较的 1—10 分矩阵，便于横向对比各 Agent。

#### 8.7.2 用户权重（P0）

**默认权重（总和 100%）：**

| 维度 | 默认权重 |
|------|----------|
| 收益潜力 | 20% |
| 成本可控性 | 20% |
| 风险可控性 | 20% |
| 技术可行性 | 15% |
| 执行可行性 | 15% |
| 长期价值 | 10% |

**规则：** 总和必须 100%；未设置则用默认。

#### 8.7.3 综合得分公式（P0）

```
综合得分 =
  收益潜力 × w1 + 成本可控性 × w2 + 风险可控性 × w3
+ 技术可行性 × w4 + 执行可行性 × w5 + 长期价值 × w6
```

综合建议参考高分 Agent，但不机械等同于「只选最高分」。

### 8.8 综合建议生成（P0）

**结构：**

1. 总体判断  
2. 主要支持理由  
3. 主要风险  
4. 分歧点说明  
5. 推荐行动方案  
6. 备选方案  
7. 最终建议  

**验收：** 非简单复制某一 Agent；体现分歧与权重；建议可执行。

| 层级 | 推荐 | 说明 |
|------|------|------|
| 前端 | Streamlit 或 PyQt6 | 老师强调 GUI 可用 PyQt；快速演示可用 Streamlit |
| API | FastAPI | A 负责路由与鉴权 |
| 数据 | SQLite | B 负责设计与 CRUD |
| AI | 本地轻量模型 + sentence-transformers | 禁止公有 LLM API |
| 并发 | asyncio / threading | P1，多 Agent 并行 |
| 拓展 | vLLM + 量化 | P2 |


## 12. 优先级规划

### P0 — 必须完成

用户注册登录、权限、问题输入、模式与 Agent 数、模板与人设、多 Agent 回答、评分矩阵、权重、综合建议、相似度（基础）、SQLite、历史、反馈、基础可视化、异常处理。

### P1 — 建议完成

Agent 推荐、冲突检测、模板管理、日志查看、雷达图/相似度图、报告导出、asyncio 并发。

### P2 — 拓展

多轮讨论、PDF/Word、3D 语义图、PyInstaller、vLLM、量化优化、真流式输出。

## 14. 项目创新点（报告/PPT 可用）

1. **动态可配置 Agent：** 2—5 个，自定义名称、背景、立场、重点、风格。  
2. **多模式决策分析：** 多角度 / 辩论 / 会诊 / 风险评审。  
3. **语义相似度控制：** 向量化 + 余弦相似度，避免「撞车」回答。  
4. **评分矩阵与用户权重：** 自然语言 → 结构化评分 + 个性化加权。  
5. **偏好反馈闭环：** 采纳结果入库，形成 RLHF 数据雏形。

## 15. 产品描述（PPT 首页可用）

> 本项目基于 Python 构建一个可配置多智能体决策辅助系统。用户输入决策问题后，可选择 Agent 数量、配置 Agent 人设、设置决策模式和权重，系统通过多个智能体生成多角度分析，并结合语义相似度、观点冲突检测、评分矩阵和可视化图表生成综合建议，最终保存用户反馈和历史记录，形成完整的 Python AI 应用开发闭环。
